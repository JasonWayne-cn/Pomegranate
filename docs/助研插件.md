# AI 助研插件设计与实现

> 目标：把助研做成独立插件，尽量不影响主程序；除宿主已有的 `plugin_settings` 外不新增数据表。

## 1. 结论

助研以 **JS 插件（`dev-plugins/research-assistant`）** 实现：

- 不新增助研专属数据表
- 不新增助研专属 Rust 命令
- 不新增宿主 npm 依赖
- 不接管主程序路由
- 通过插件自己的侧边栏入口与全屏面板呈现

唯一的宿主增强是 **通用受控 HTTP 代理**（`network:request`），用于访问 6 个公共论文源；它不是助研专用逻辑，其他插件也可复用。

## 2. 为什么选插件而不是 Engine Pack

| 维度 | JS 插件 | Engine Pack |
|---|---|---|
| 运行位置 | 宿主 WebView | Python/可执行子进程 |
| UI | 自己渲染 | 宿主必须提供页面 |
| 数据 | `plugin_settings` KV | 扩展/作业表 + workspace |
| 宿主改动 | 几乎为零 | loader + service + 表 + 页面 |
| 适合 | UI + AI 编排 + 轻量检索 | 重计算、文件生成、PDF/OCR/ML |

助研主体是页面、文献管理、检索与 AI 写作，不需要独立计算进程，因此插件更合适。

## 5. 生命周期与入口

`main.js` 导出：

```js
module.exports = { onLoad, onUnload };
```

`onLoad(ctx)`：

1. `app.sidebar.addItem(...)` 注册「AI 助研」侧边栏
2. `app.panelViews.register(...)` 注册全屏面板
3. `app.commands.addCommand(...)` 注册命令面板入口

`onUnload()` 清理注册。

面板渲染函数返回 cleanup，宿主切换视图时销毁 DOM。

## 6. 数据存储（免表）

全部写入宿主现有 `plugin_settings`，宿主自动按 `pluginId` 加前缀隔离。

| Key | 内容 |
|---|---|
| `meta` | `{ version, activeProjectId, projects[] }` |
| `lit:<projectId>` | 当前课题文献数组 |
| `out:<projectId>` | 当前课题产出数组 |
| `cache:<hash>` | 检索结果缓存（含 `expiresAt`） |
| `settings` | 模型、启用的来源、缓存时长、最大结果数 |

写入策略：

- 单写队列，避免并发覆盖
- 只在操作完成后写入，不按每次击键写入
- 不保存 PDF 全文，只保存分析结果与摘要
- 单课题建议上限：文献 500 条、产出 200 条

## 7. 页面信息架构

```
AI 助研
```

- 不使用 React / Ant Design

## 8. 论文源与 HTTP 代理

### 8.1 来源

| 来源 | 说明 |
|---|---|
| Crossref | 跨学科出版物 |
| Europe PMC | 生命科学与医学 |
| arXiv | 前沿预印本 |
| DBLP | 计算机科学 |
| PubMed | 生物医学 |
| Semantic Scholar | 跨学科学术图谱 |

### 8.2 宿主代理

新增通用命令：

```
plugin_proxy_http_request(token, request)
```

安全约束：

- 必须携带插件 token 且拥有 `network:request`
- 仅允许 HTTPS
- 仅允许白名单域名：
  - `api.crossref.org`
  - `www.ebi.ac.uk`
  - `export.arxiv.org`
  - `arxiv.org`
  - `dblp.org`
  - `eutils.ncbi.nlm.nih.gov`
  - `api.semanticscholar.org`
- 仅允许 GET / POST
- 请求体 ≤ 100KB，响应体 ≤ 5MB
- 超时 5–30 秒
- 禁用自动重定向，防止 302 绕过白名单
- 只透传 `accept` / `content-type`，忽略 Cookie / Authorization

前端通过 `app.http.request()` 调用，token 由插件运行时闭包持有，插件 JS 无法直接读取。

### 8.3 缓存

- 缓存键：查询 + 年份 + 来源 + 结果数，带 `cache:v2:` 版本前缀
- 默认 24 小时
- 命中缓存时直接展示，并提示“已使用缓存结果”
- **全部来源不可用 / 权限拒绝的结果不写入缓存**；旧版失败缓存通过 v2 前缀自动失效
- 设置页可清理 `cache:*`

### 8.4 查询构造与准确度

- 关键词按 `, ， ; ； 、 | 空格 换行` 拆分
- 中文查询默认自动调用 AI 生成英文检索式（设置中可关闭）
- Crossref 使用 `query.bibliographic` + `sort=relevance`
- Crossref 同时跑中文原查询与英文扩展查询，合并去重
- arXiv / DBLP / PubMed / Semantic Scholar 使用英文检索式；没有英文扩展时跳过并提示
- 每个来源扩大候选池（15–30 条），再统一去重与排序

### 8.5 去重与排序

- DOI 小写精确匹配优先
- 无 DOI 时使用“规范化标题 + 年份”
- 合并多来源链接，引用量取最大值，摘要取更长者
- 相关度：标题/摘要关键词命中 + 来源返回顺序
- 综合分：

```
0.55 × 相关度
+ 0.20 × 年份新近度
+ 0.10 × log(引用量)
+ 0.15 × 多来源收录数
```

- 列表默认按相关度排序，可切换综合分 / 年份 / 引用量
- 每篇论文显示“相关度”和“综合分”
- 检索缓存升级为 `cache:v3:`，旧缓存自动失效

## 9. 从资料提取检索词

「发现」页提供「从资料提取」按钮，支持三类来源：

| 来源 | 实现 |
|---|---|
| 已有文档 | `app.notes.search` / `app.notes.list` + `app.notes.get` |
| 本地文献 | `plugin:dialog|open` + `ppt_extension_extract_local_file` |
| 文献库 | 当前课题 `state.literature` 的题录、摘要与笔记 |

本地文献支持 md / txt / pdf / doc / docx / xlsx / csv，复用 PPT 扩展的文本抽取命令，不依赖 PPT 扩展包是否安装。

限制：

- 最多 12 个来源；本地文件最多 5 个
- 单源最多 12,000 字符，总上下文最多 24,000 字符
- 隐藏 / 加密 / 临时 / 非 Markdown 文档自动跳过
- 只发送用户明确勾选的内容

AI 返回 JSON：

```json
{
  "topic": "",
  "topicCandidates": ["", "", ""],
  "keywords": [""],
  "researchQuestions": [""],
  "methods": [""],
  "domain": "",
  "confidence": 0.0,
  "warnings": [""]
}
```

结果处理：

- 前端清洗：去重、长度过滤、空关键词回退课题关键词
- AI 不可用时使用本地规则兜底，并标注 `local_fallback`
- 成功结果缓存到 `extract:v1:<hash>`，有效期 7 天；本地兜底不缓存
- 最近 10 次提取保存在 `extractHistory`

结果确认面板支持：

- 编辑主题、选择候选主题
- 增删关键词
- 保存为课题关键词
- 应用到检索 / 应用并检索

## 10. AI 工作流

通过 `app.ai.chatSync(messages, { modelId? })` 调用默认模型。

模式：

| 模式 | 输入 | 输出 |
|---|---|---|
| frontier | 主题 + 课题上下文 | 热点 / 趋势 / 机会 / 检索式 / 证据边界 |
| review | 勾选文献 + 主题/材料 | 背景 / 脉络 / 对比表 / 缺口 / 问题 / 参考文献 |
| outline | 题目/主题 + 材料 | 题目 / 摘要 / 关键词 / 章节 / 方法 / 风险 |
| polish | 原文 + 风格 | 润色后文本 + 修改说明 |
| format | 原文 + 检查重点 | 问题清单 + 修订稿 + 待确认 |
| analyze | 数据/材料 + 问题 | 数据概况 / 分析 / 观察 / 可视化 / 局限 |

统一约束：

- 不得虚构论文、作者、DOI、年份、数据
- 无法确认的信息标注“待检索验证”
- 只输出 Markdown 正文
- AI 建议只作筛选参考，最终由用户确认

## 11. PDF 精读

零新增 Rust 命令：

1. `app.invoke("plugin:dialog|open", { options: { multiple: true, filters: [...] } })`
2. `app.invoke("ai_parse_attachment", { filePath })`
3. 截断到 30,000 字符/篇
4. `app.ai.chatSync` 要求输出 JSON
5. 解析失败时展示原文，不写入半成品

分析结果：

- 项目理解
- 逐篇论文：摘要、关键词、方法、数据/实验、结论、局限
- 共同关键词
- 跨论文异同
- 项目建议
- SVG 知识图谱

图谱使用手写 SVG 径向布局，不引入 Cytoscape，避免 `main.js` 体积膨胀。

## 12. 知识库

- 通过 `list_folders` 查找「论文知识库」
- 不存在则 `create_folder`
- `app.notes.create` 写入笔记
- 文献笔记使用 `<!-- research-paper:<identity> -->` 标记
- 产出笔记使用 `<!-- research-output:<id> -->` 标记
- 删除走现有回收站逻辑，不物理删除

### 12.1 参考文献索引导出

文献库工具栏新增「导出参考文献」：

- 仅导出当前勾选的文献
- 支持两种格式：
  - `GB/T 7714` 风格编号参考文献表
  - `BibTeX`
- 预览后可：
  - 复制到剪贴板
  - 下载 `.md` / `.bib`
  - 保存为「论文知识库」中的笔记
- 作者超过 3 位时，中文追加“等”，英文追加“et al.”
- 类型映射：期刊 `[J]`、会议 `[C]`、预印本 `[EB/OL]`、书籍章节 `[M]`、学位论文 `[D]`、报告 `[R]`
- 缺失字段留空并提示人工核对

## 15. 卸载与重装的数据保留

`plugin_settings.plugin_id` 带 `ON DELETE CASCADE`，直接删除插件记录会连带删除插件数据。

宿主已在卸载时做保护：

1. 卸载前把 `plugin_settings` 备份到 `<数据目录>/plugin-data-backups/<plugin-id>.json`
2. 重装成功后自动恢复到 `plugin_settings`
3. 恢复成功即删除备份文件

注意：权限授权不会自动恢复，重装后仍需在插件详情中重新授权。

## 16. 已知限制

- 插件 UI 不使用 Ant Design，视觉细节与宿主设置页不完全一致。
- `app.invoke` 是宿主通用透传，插件属于“安装即信任”模型。
- 扫描版 PDF 无法抽取文本时需要用户改为粘贴文本。
- 在线论文源依赖公共 API，可能限流或暂时不可用。
- 插件数据在 `plugin_settings` 中，暂不参与宿主笔记同步；可通过“导出全部数据”备份。
- 旧内置助研的三张表不会自动删除；确认不再需要后可手动迁移删除。
