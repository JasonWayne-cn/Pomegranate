一句话：**沿用 P3D 插件的"静态查看器 + 本机服务 + iframe"思路，但把 P3D 的独立 sidecar 换成主程序内的只读静态服务，把 P3D 私有格式引擎换成 Online3DViewer 的多格式离线引擎，并接入 Pomegranate 已有的扩展包安装/验签/回滚体系。**

## 2. 参考项目分析

### 2.1 W-MD Viewer 的 P3D 插件

关键代码：

| 文件 | 作用 |
| --- | --- |
| `p3dviewer-plugin/p3d-sidecar/src/main.rs` | sidecar 入口：stdout JSON 协议（ready / heartbeat / error / log），stdin 接收 shutdown / set_pending_file |
| `p3dviewer-plugin/p3d-sidecar/src/server.rs` | `tiny_http` 回环服务：`include_dir!` 把查看器静态资源编译进 exe；`/viewer/*` 出静态资源，`/file/<base64url>` 读用户模型 |
| `src-tauri/src/plugin_manager/sidecar.rs` | 子进程生命周期：等待 ready（10s 超时）、捕获 stderr 诊断、stdout 排泄线程、Drop 时 shutdown→kill |
| `src-tauri/src/plugin_manager/mod.rs` | `plugins.json` 注册表、zip 安装/卸载、出厂 zip 自动安装、manifest 校验 |
| `src/plugins/p3d-viewer/P3DViewerPanel.tsx` | iframe + postMessage：`p3d-ready` / `p3d-heartbeat` / `p3d-error`，30s 超时、5 次心跳丢失判死、强制重建 iframe |
| `src/plugins/p3d-viewer/p3d-store.ts` | 插件状态机：`not_installed` / `installed` / `running` / `error`；按需自动启动；URL 生成 |
| `src-tauri/src/commands/p3d_viewer.rs` | 文件关联打开独立全屏 `WebviewWindow`，先起 sidecar 再跳 `/viewer` 路由 |

**值得借鉴**

1. **静态资源与模型都经本机 HTTP 服务**：WebView 里加载 WASM、Worker、多文件模型最稳，绕开自定义协议对相对路径、MIME、Worker 的限制。
2. **iframe + postMessage 状态机**：ready / 进度 / 错误 / 心跳，配合超时 + 重建 iframe，能覆盖"渲染线程被长解析阻塞"的场景。
3. **插件 zip 独立版本化**：查看器引擎与主程序解耦，可单独更新。
4. **sidecar stderr 保留**：启动失败时把 stderr 拼进错误信息，避免"进程意外退出"无诊断信息。

**不照搬的地方**

1. **不需要独立 sidecar exe**：P3D 需要 sidecar 是因为其内核为私有/旧式 JS + WASM 运行环境且希望崩溃隔离。Online3DViewer 是纯前端静态资源，主程序内起一个只读 HTTP 线程即可，省掉 Win7 交叉编译、杀软误报、sidecar 升级包。
2. **不要 `include_dir!` 编译进主程序**：查看器包有十几 MB（含 OCCT/IFC WASM），打进主 exe 会让每次主程序更新都变重。放在扩展包目录、按需服务。
3. **P3D 的 base64 路径拼 URL 只适合单文件**：多文件格式（OBJ+MTL+纹理、glTF+bin）需要目录级白名单解析，见 §8.3。

### 2.2 Online3DViewer

**架构**

```
source/engine/import/*    → 16 个 Importer（按扩展名路由）
source/engine/model/*     → 与渲染无关的模型层（Node/Mesh/Material/Property/Topology）
source/engine/threejs/*   → Model → three.js 场景转换（ThreeModelLoader/ThreeConverter）
source/engine/viewer/*    → Viewer（WebGLRenderer）、EmbeddedViewer（嵌入 API）、导航/着色
source/engine/export/*    → 导出 3dm/bim/gltf/obj/off/stl/ply
source/website/*          → 3dviewer.net 完整站点 UI（被设计为禁止 iframe 嵌入）
```

**可直接使用的嵌入 API**（`main.js` 导出，构建为全局 `OV`）：

```js
const viewer = OV.Init3DViewerFromUrlList(container, [
  "/m/model.step",
  // 可选：/c/xxx.mtl、/c/tex.png ...
], {
  backgroundColor: new OV.RGBAColor(30, 30, 30, 255),
  defaultColor: new OV.RGBColor(200, 200, 200),
  edgeSettings: new OV.EdgeSettings(...),
  projectionMode: OV.ProjectionMode.Perspective,
  onModelLoaded: () => {},
  onModelLoadFailed: () => {},
});
```

加载回调链：`onLoadStart → onFileListProgress → onFileLoadProgress → onImportStart → onVisualizationStart → onModelFinished → onTextureLoaded`，足以驱动 UI 进度条。

**格式与外部依赖（必须离线化）**

| 格式 | 导入器 | 外部依赖 | 离线处理 |
| --- | --- | --- | --- |
| stl/obj/off/ply/3ds/gltf/glb/3mf/amf/dae/fbx/wrl | 内置解析或 three loader | fflate；glTF Draco 需 `draco3d` | vendor draco 到包内 |
| step/stp/iges/igs/brep/fcstd | `ImporterOcct` | `occt-import-js`（CDN worker + wasm，约 11.7MB 解压） | vendor 完整 dist，改写 worker 的 baseUrl |
| 3dm | `Importer3dm` | `rhino3dm`（CDN，约 3.4MB 解压） | vendor dist |
| ifc | `ImporterIfc` | `web-ifc`（CDN，约 21.9MB 解压，实际只需部分 wasm） | vendor 所需 wasm 子集 |

当前源码中依赖是**运行时从 jsDelivr 拉取**的：\
`source/engine/import/importerutils.js` 的 `LoadExternalLibrary()` 与 `CreateOcctWorker()`。\
桌面离线场景必须构建期改写为包内相对路径。

**许可**：Online3DViewer MIT；three.js MIT；rhino3dm MIT；web-ifc MPL-2.0；draco Apache-2.0；OCCT / occt-import-js 涉及 LGPL（需附许可证、提供源码获取方式、允许替换）。扩展包独立安装目录天然满足"可替换"，但仍需法务确认静态 WASM 分发方式。

## 3. 方案对比

| 维度 | A. 扩展包 + 主进程回环服务（推荐） | B. 现有 JS 插件运行时（`new Function`） | C. 独立 sidecar（照搬 P3D） | D. 直接编进主程序 |
| --- | --- | --- | --- | --- |
| 复用现有设施 | 扩展包：安装/验签/回滚/版本目录 | 插件管理/令牌/权限 | 需新写插件注册表 | 无 |
| WASM / Worker / 多文件 | ✅ 标准 HTTP，最稳 | ❌ 现有 `readAsset` 只读文本且限 2MB，需扩展二进制 API | ✅ | ✅ |
| 崩溃/卡死隔离 | iframe 隔离，主进程不受影响 | ❌ 与 React 同上下文，长解析卡 UI | ✅ 独立进程 | ❌ |
| 体积与更新 | 引擎 15–25MB，独立更新 | 引擎仍在主包或需 blob | sidecar 额外编译/杀软风险 | 主安装包永久变大 |
| Win7 | 无需新 Rust 二进制；主进程新增小模块 | 同左 | 需为 Win7 单独编译 sidecar | 同左 |
| 安全 | 回环 + 会话令牌 + 路径白名单 + 扩展签名 | 插件 JS 权限模型，但 asset 能力不足 | 同 A，但进程间协议更多面 | 信任链最短 |
| 结论 | **采用** | 不满足二进制资产 | 备选（未来需要强隔离时） | 不采用 |

**为什么不走 B**：现有插件运行时的 `readAsset` 读取 UTF-8 文本且限制 2MB，无法承载 WASM/纹理解码器；把二进制改成 base64 再在页面里拼 blob URL，Worker 内部相对路径与 wasm 定位会非常脆弱。

**为什么不走 C**：与 P3D 不同，我们没有必须独立进程的私有内核；sidecar 会引入 Win7 构建、PE 导入门禁、签名、杀软与升级包复杂度，收益仅是崩溃隔离，而 iframe 已经提供了足够的"渲染层隔离 + 重建"能力。

## 4. 总体架构

```
┌──────────────────────────── Pomegranate 主进程（Rust）────────────────────────────┐
│                                                                                   │
│  commands/viewer3d.rs                                                             │
│    viewer3d_status / viewer3d_open / viewer3d_close / viewer3d_open_window        │
│            │                                                                      │
│            ▼                                                                      │
│  services/viewer3d/                                                               │
│    ├── mod.rs          Viewer3dState（服务器句柄 + 会话表）                       │
│    ├── server.rs       tiny_http 线程：127.0.0.1:0，路由 + 令牌 + 路径守卫         │
│    ├── session.rs      会话创建/回收（模型根目录、文件白名单、TTL）                │
│    ├── companions.rs   OBJ/glTF 引用文件解析（可选）                              │
│    └── assets.rs       MIME、缓存头、CSP、Content-Type（含 .wasm）                │
│            │                                                                      │
│            └── 只读读取 app_data/extensions/viewer3d/versions/<ver>/              │
│                                                                                   │
└───────────────────────────────────────────────────────────────────────────────────┘
                                  ▲  HTTP 127.0.0.1:<随机端口>（令牌在路径前缀）
                                  │
┌──────────────────────────── WebView（React）──────────────────────────────────────┐
│  src/components/preview/Viewer3DPreview.tsx                                       │
│    ├─ invoke("viewer3d_open", { path }) → { url }                                 │
│    ├─ <iframe src={url} sandbox="allow-scripts allow-same-origin">                │
│    └─ postMessage 状态机：ready / progress / loaded / error / heartbeat           │
│                                                                                   │
│  ┌──────────────────── iframe（同源：127.0.0.1 查看器包）──────────────────────┐ │
│  │  viewer/index.html + host.js                                                  │ │
│  │    ├─ GET /v/<sid>/<token>/assets/...  ← o3dv.min.js / wasm / worker        │ │
│  │    ├─ GET /v/<sid>/<token>/m/<文件名>  ← 模型主文件                          │ │
│  │    ├─ GET /v/<sid>/<token>/c/<相对路径> ← 伴生文件（mtl/bin/纹理）          │ │
│  │    └─ OV.Init3DViewerFromUrlList(container, urls, params)                    │ │
│  └───────────────────────────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────────────────────┘
```

设计原则：

1. **Rust 只做三件事**：找扩展包、发会话 URL、安全地吐字节。不解析模型、不碰 WebGL。
2. **引擎完全不感知 Tauri**：同一套 `viewer/` 目录在浏览器里也能跑，便于开发调试。
3. **模型路径不出主进程**：iframe 只见过 `/m/<文件名>` 与会话令牌，真实绝对路径只存在于 Rust 会话表。

## 5. 扩展包设计

### 5.1 目录结构

```
viewer3d-v1.2.0-win-x64.zip
├── extension.json
├── checksums.json               # 逐文件 sha256（可选签名）
├── LICENSES/
│   ├── Online3DViewer-MIT.txt
│   ├── three-MIT.txt
│   ├── OCCT-LGPL.txt
│   ├── web-ifc-MPL-2.0.txt
│   └── rhino3dm-MIT.txt
└── viewer/
    ├── index.html               # 宿主页
    ├── host.js                  # 引擎初始化 + postMessage 协议
    ├── o3dv.min.js              # Online3DViewer 引擎（esbuild 产物）
    ├── styles.css
    ├── vendor/
    │   ├── draco/               # draco_decoder.js/.wasm
    │   ├── occt/                # occt-import-js-worker.js + .js + .wasm
    │   ├── rhino3dm/            # rhino3dm.min.js（+ wasm，如有）
    │   └── web-ifc/             # web-ifc-api-iife.js + .wasm

所有资源均由扩展包目录提供；发布包不含任何 CDN 地址。

        "cad": ["step", "iges", "brep", "fcstd"],

    }
  },
  "integrity": {

```

现有 `ExtensionService` 的校验逻辑已支持任意 `runtime.type`（`validate_manifest` 只校验 `apiVersion/protocolVersion/entry` 存在），因此：

- 新增 `runtime.type = "web"` 语义：**不启动子进程，只作为静态资源根**；
- `ExtensionRunner` 不需要改动（web 类型不会被 PPT 作业调用）；
- `extension.json` 的 `contributes.viewer3d` 由新模块读取，不污染 PPT 逻辑。

### 5.3 版本与更新

- 安装路径沿用 `app_data/extensions/viewer3d/versions/<version>/`，`current.json` 指向当前版本；
- 复用 `extension_install_zip` / `extension_rollback` / `extension_verify`；
- 内置包分发参考 `ppt-master` 的 bundled 逻辑：安装器把 `viewer3d-extension.zip` + `.version` 放到 resources，首次启动自动安装（可退订）；
- 在线更新可复用现有 `update.json` / 扩展下载通道；下载完成后再走 `extension_install_zip` 的统一校验。

### 5.4 格式包拆分（可选）

| 包 | 内容 | 压缩后大致体积 | 默认 |
| --- | --- | --- | --- |
| core | 引擎 + DAE/FBX/WRL/3MF/AMF + fflate | 2–3MB | 必装 |
| cad | occt-import-js（11.7MB 解压） | 5–7MB | 可选 |
| bim | web-ifc 所需 wasm 子集 | 3–5MB | 可选 |
| rhino | rhino3dm dist | 1–2MB | 可选 |

首期建议直接发**单一完整包**（约 15–20MB 压缩后），减少扩展包依赖管理；若主安装包体积敏感，再拆分为 `viewer3d-core` + 按格式下载的附加包。拆分时扩展清单用 `dependencies` 或 `provides` 字段扩展（需同步升级扩展协议版本，不在首期）。

## 6. Rust 侧设计

### 6.1 状态

```rust
// services/viewer3d/mod.rs
pub struct Viewer3dState {
    /// 回环服务器（首次使用时启动，应用生命周期内常驻；端口随机）
    server: Mutex<Option<Viewer3dServer>>,
    /// 活跃会话：sid -> session
    sessions: Mutex<HashMap<String, Viewer3dSession>>,
}

pub struct Viewer3dSession {
    pub sid: String,
    pub token: String,           // 32 字节随机，十六进制
    pub root: PathBuf,           // 模型文件所在目录（canonicalize 后）
    pub main: PathBuf,           // 主文件（canonicalize 后）
    pub main_name: String,       // 保留原文件名与扩展名，供引擎判断格式
    pub allowed_exts: HashSet<String>,
    pub created_at: Instant,
    pub last_access: Arc<Mutex<Instant>>,
    pub total_bytes_served: AtomicU64,
}
```

挂到 `AppState`：

```rust
pub struct AppState {
    // ...
    pub viewer3d: Viewer3dState,
}
```

### 6.2 Commands（IPC 入口）

| Command | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| `viewer3d_status` | — | `{installed, enabled, version, serverPort?, formats[]}` | 供预览组件显示"未安装/可预览" |
| `viewer3d_open` | `{ path, options? }` | `{ sessionId, url, fileName, format }` | 解析真实路径→校验扩展名/大小→建会话→返回 iframe URL |
| `viewer3d_close` | `{ sessionId }` | `()` | 删除会话（模型字节不再可访问） |
| `viewer3d_open_window` | `{ sessionId }` | `()` | 可选：用 `WebviewWindowBuilder` 打开 `/viewer3d?sid=...` 全屏窗口 |
| `viewer3d_list_companions` | `{ sessionId }` | `{files:[]}` | 调试/手动补文件场景（正常由 HTTP `/manifest` 提供） |

三层职责：

- **Command**：参数校验、错误转 `String`；
- **Service**：扩展包定位、会话生命周期、路径/格式/大小校验、服务器启动；
- **Server**：纯 HTTP 与字节流，不访问数据库。

### 6.3 回环服务器

选型：`tiny_http`（参考 P3D，纯 std、无线程池依赖、Win7 友好）。单线程 `recv_timeout(500ms)` 循环 + 关闭标志；静态资源读取为内存映射式 `fs::read`（模型通常 &lt; 512MB，可改流式）。

**启动**：`bind("127.0.0.1:0")`，失败重试 3 次；端口写入 `Viewer3dState`。\
**常驻**：首次 `viewer3d_open` 时启动，应用退出随进程结束；避免频繁 bind/unbind 导致的端口竞争。\
**会话回收**：后台线程每 60s 清理 `last_access > 10min` 的会话；`viewer3d_close` 立即删除；最多 4 个并发会话（超出先逐出最旧）。

### 6.4 HTTP 路由

前缀统一：`/v/{sid}/{token}/`

| 方法 | 路径 | 处理 |
| --- | --- | --- |
| GET/HEAD | `/v/{sid}/{token}/` | `viewer/index.html`（注入可选主题参数） |
| GET/HEAD | `/v/{sid}/{token}/assets/{rel}` | 扩展包 `viewer/` 下的静态资源；强缓存 1 年 |
| GET/HEAD | `/v/{sid}/{token}/m/{name}` | 主模型文件（`name` 必须等于会话主文件名） |
| GET/HEAD | `/v/{sid}/{token}/c/{rel}` | 伴生文件；`rel` 相对模型目录，仅允许白名单扩展名 |
| GET | `/v/{sid}/{token}/manifest` | `{main_url, files:[...]}`，供宿主页一次性拿全文件列表 |
| GET | `/v/{sid}/{token}/health` | `200 "ok"`，父页面可选探活 |

**响应头**

```
Content-Type: application/wasm | application/octet-stream | ...
X-Content-Type-Options: nosniff
Cache-Control: (assets) public, max-age=31536000, immutable ; (model) no-store
Cross-Origin-Resource-Policy: same-origin
Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval';
  worker-src 'self' blob:; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'
```

（`wasm-unsafe-eval` 供 Emscripten 实例化；`worker-src blob:` 供 OCCT worker 的 Blob 方案。）

### 6.5 路径与令牌守卫（核心安全逻辑）

1. 会话创建时：
   - `fs::canonicalize(path)`；必须是普通文件；扩展名在扩展包声明列表内；
   - 文件大小 ≤ `maxModelBytes`；
   - `root = canonical.parent()`；记录主文件名。
2. 每次请求：
   - 先校验 `sid` 存在、`token` 与常量时间比较（定长十六进制可直接 `==`，避免提前返回差异）；
   - 更新 `last_access`；
   - `assets/{rel}`：`safe_join(viewer_root, rel)` + `canonicalize` + `starts_with(viewer_root)`；禁止 `..`、绝对路径、符号链接逃逸；
   - `c/{rel}`：同上，根为 `session.root`；扩展名必须在 `allowed_exts ∪ {mtl,bin,png,jpg,jpeg,webp,ktx2,tga,dds,glb}` 内；单文件 ≤ 512MB，单会话累计读取 ≤ 2GB；
   - 不存在/越界统一 `404`，不返回目录列表，不在响应体泄露绝对路径。
3. 只接受 `Host: 127.0.0.1:<port>` 或 `localhost:<port>`（防 DNS rebinding）。
4. 不开放 `POST`/`PUT`/`DELETE`；不实现跨域（同源 iframe 不需要 CORS）。

### 6.6 伴生文件解析（`companions.rs`）

Online3DViewer 的 `LoadModelFromUrlList` 要求调用方把主文件**和所有被引用文件**一起传入，否则导入失败。策略：

| 主文件 | 解析方式 |
| --- | --- |
| `.zip` | 不解析。引擎内部用 fflate 解压，推荐多文件模型直接打包 zip |
| `.gltf` | 解析 JSON：`buffers[].uri`、`images[].uri`（跳过 `data:`），只保留相对路径且存在于 `root` 的文件 |
| `.obj` | 读取前 256KB 文本，提取 `mtllib`；对每个 mtl 再读取前 256KB，提取 `map_*` 引用的纹理名；均做存在性检查 |
| `.dae/.fbx/.3ds` | 首期：若同目录存在与主文件同名或文本中出现且存在的常见纹理文件（png/jpg/jpeg/dds/tga），最多 32 个；否则仅主文件 |
| 其他 | 仅主文件 |

限制：最多 64 个伴生文件、累计 ≤ 512MB；解析失败不影响主文件加载，只返回空列表。UI 侧提供"手动选择关联文件"作为兜底（多选后建立额外会话文件映射，属于二期）。

### 7.4 postMessage 协议

父 → iframe：

```json
{ "type": "viewer3d:set-theme", "background": "#1e1e1e", "edges": true }
{ "type": "viewer3d:fit" }
{ "type": "viewer3d:projection", "mode": "perspective" }
{ "type": "viewer3d:snapshot", "requestId": "..." }
{ "type": "viewer3d:dispose" }
```

iframe → 父：

```json
{ "type": "viewer3d:ready", "formats": ["stl", "step"] }
{ "type": "viewer3d:progress", "stage": "import", "current": 1, "total": 3 }
{ "type": "viewer3d:heartbeat", "t": 1699999999 }
{ "type": "viewer3d:loaded", "meshes": 12, "triangles": 345678, "bbox": [..] }
{ "type": "viewer3d:error", "code": "import_failed", "message": "..." }
{ "type": "viewer3d:snapshot", "requestId": "...", "dataUrl": "data:image/png;base64,..." }
```

父页面校验：

```ts
if (e.source !== iframeRef.current?.contentWindow) return;
if (e.origin !== expectedOrigin) return;          // 由 viewer3d_open 返回 origin
if (typeof e.data?.type !== "string" || !e.data.type.startsWith("viewer3d:")) return;
```

超时/心跳常量参考 P3D 的踩坑结论：

- 首帧超时 30s（慢盘/Win7 可放宽到 60s）；
- 心跳间隔 2s，连续丢失 5 次判"渲染无响应"；
- **消息监听器只注册一次**，不要依赖 `loading/error` 状态重建（P3D 曾因此反复重置心跳计数）；
- 心跳恢复时自动解除错误遮罩（模型解析结束会恢复事件循环）。

### 7.5 iframe 属性

```html
<iframe
  src={url}
  sandbox="allow-scripts allow-same-origin allow-downloads"
  referrerpolicy="no-referrer"
  style="width:100%;height:100%;border:0"
/>
```

不授予 `allow-top-navigation` / `allow-popups` / `allow-modals`，防止查看器内脚本影响主界面。

## 8. 引擎离线化与构建

### 8.1 上游固定与补丁

- 固定 Online3DViewer 源码 commit（建议与 0.19 开发线一致，记录 SHA）；
- 补丁文件放 `scripts/viewer3d/patches/`：
  1. `importerutils.ts/js`：`CreateOcctWorker` 的 `baseUrl` 改为 `new URL('./vendor/occt/', import.meta.url)` 或宿主注入的 `window.__O3DV_VENDOR__`；
  2. `LoadExternalLibrary()`：`rhino3dm` / `webifc` / `draco3d` 改为包内相对 URL（或预加载全局对象，不再动态插 script）；
  3. 可选：移除 `StartWebsite` 的 iframe 禁止逻辑（仅在使用完整站点 UI 时）。
- 用 `git apply` 或直接维护一个最小 fork；构建脚本校验补丁可干净应用。

### 8.2 构建脚本

新增 `scripts/build-viewer3d-pack.mjs`：

```
1. 下载/解压固定版本上游源码（URL + sha256 校验，或本地 third_party 目录）
2. 应用 patches/
3. npm ci
4. npm run build_engine            # esbuild → o3dv.min.js（全局 OV）
5. esbuild host.ts → viewer/host.js
6. 复制 vendor：draco / occt / rhino3dm / web-ifc（按格式包选择）
7. 复制 viewer/index.html、styles.css、LICENSES
8. 生成 extension.json + checksums.json（逐文件 sha256）
9. 可选 Ed25519 签名（复用扩展签名密钥）
10. 打包 zip，输出 viewer3d-<version>-<platform>.zip 与 .version
```

产物不进入主仓库（体积大）；可通过 release 附件分发。CI 可缓存上游 tarball。

### 8.3 宿主页职责（`viewer/host.js`）

1. 解析 URL 查询参数：`?sid=...` 仅用于日志，不含真实路径；
2. `fetch('./manifest')` 拿 `files[]`；
3. 构造 `OV.RGBAColor` 等参数（背景/边线/投影来自父页面 postMessage 或默认值）；
4. `OV.Init3DViewerFromUrlList(container, files, callbacks)`；
5. 回调映射为 `viewer3d:*` 消息；
6. `setInterval` 心跳 2s；`window.addEventListener('resize')` 调 `viewer.Resize()`；
7. 收到 `dispose` 时 `viewer.Destroy()` 并停心跳。

> 引擎的 `EmbeddedViewer` 已自动处理容器尺寸与窗口 resize；宿主页只需在 `loaded` 后发消息。

## 9. 安全设计

| 面 | 措施 |
| --- | --- |
| 端口暴露 | 只绑定 `127.0.0.1`；随机端口；校验 Host 头 |
| 未授权访问 | 每会话 32 字节随机令牌，位于 URL 路径；关闭会话即失效；令牌 10 分钟无访问过期 |
| 路径穿越 | 所有路径 `canonicalize` + `starts_with(root)`；拒绝 `..`、绝对路径、符号链接逃逸；无目录列表 |
| 任意文件读取 | 主文件必须由用户动作选择；伴生文件限制在模型所在目录 + 扩展名白名单；不提供"按绝对路径读取"的通用接口 |
| 资源耗尽 | 单文件 512MB、单会话累计 2GB、最多 4 会话、心跳超时自动提示、会话 TTL |
| 扩展包篡改 | 复用 `ExtensionService` 内容哈希；发布包可选 Ed25519 签名；安装前预检 zip 路径穿越/文件数/大小 |
| 渲染层 | iframe sandbox，无 top navigation / popup；CSP 限制连接源为 self |
| 数据泄露 | 扩展包静态资源可被同机其他进程按端口猜中？令牌随机 256 位，且每次会话不同；响应不含真实路径 |
| 供应链 | 上游 commit + tarball sha256 固定；vendor 库版本锁定；构建产物生成 checksums |
| 模型解析崩溃 | OCCT 在 Worker 中执行；WebView 渲染崩溃只影响 iframe，父页面重建 iframe；主进程/Rust 不受影响 |

Tauri 配置需要同步修改：

```json
// src-tauri/tauri.conf.json → app.security.csp
"frame-src ... http://127.0.0.1:* http://localhost:*"
```

新增窗口时同步 `capabilities/default.json` 的 `windows` 列表（`viewer3d-*`）。

## 11. 性能与资源

- **按格式懒加载**：宿主页只在需要时创建 OCCT Worker；rhino3dm/web-ifc 通过 `<script>` 按需插入本地 URL，避免首屏加载 20MB。
- **静态资源强缓存**：扩展包版本化目录 + `immutable`，切换模型不重复下载 WASM。
- **会话复用**：同一文件重复打开复用会话（按主文件 canonical path + mtime 哈希），避免重复授权。
- **关闭即销毁**：Modal 关闭发 `dispose` → `viewer.Destroy()`；父组件卸载立即 `viewer3d_close`；iframe `key` 重建用于崩溃恢复。
- **渲染设置**：默认关闭环境贴图（省 6 张 jpg 与采样开销）；边线按模型大小自动降级；透视/正交可切换。
- **大模型**：&gt; 200MB 时提示"可能较慢"；引擎解析在 Worker（OCCT）或主线程（其他），心跳缺失时保留 iframe 而非直接关闭。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| OCCT LGPL / web-ifc MPL 合规 | 发布受阻 | 随包附 LICENSES；提供上游源码与替换说明；发布前法务确认 |
| Win7 WebGL2 不可用/软渲染极慢 | 功能不可用或体验差 | 启动检测 + 明确提示 + "系统应用打开"兜底；默认关闭环境贴图/边线 |

| CDN 残留导致断网失败 | 离线不可用 | E2E 断网门禁 + 构建后扫描产物中的 `http(s)://` |

| 回环端口被本机恶意进程访问 | 数据泄露 | 随机端口 + 256 位会话令牌 + 关闭即失效 + Host 校验 |
| 扩展包体积大/更新慢 | 首次体验差 | 按格式拆包（二期）+ 强缓存 + 下载进度 |

## 附录 B：当前已落地实现（内置核心查看器）

在扩展包方案完整落地前，先实现了**不依赖扩展包**的内置查看器，保证"文档内插入三维模型"可用：

| 能力 | 实现 |
| --- | --- |
| 离线引擎 | `public/viewer3d/o3dv.min.js`（Online 3D Viewer 0.18 全局构建，含 three/fflate） |
| 模型读取 | `src/services/viewer3d.ts`：`resolve_asset_absolute_path` → `read_file_as_base64` → `File`，绕开 asset 协议 CORS |
| 预览 UI | `src/components/preview/Viewer3DPreview.tsx`：按需加载引擎、ResizeObserver、销毁释放 WebGL |
| 文档节点 | `src/components/editor/Viewer3DNode.ts` + `Viewer3DNodeView.tsx`，存 `kb-asset://`，卡片点开预览 |
| 工具栏 | 编辑器"插入"下拉新增「插入三维模型」，文件落 `kb_assets/attachments/<note_id>/` |
| 附件路由 | `attachmentPreview` 白名单 + Modal 三维分支；三维链接点击直接进应用内预览 |
| 桌面预览 Modal | 挂在笔记编辑页根部（`src/pages/notes/editor.tsx`），随路由卸载 |
| 模型结构树 | 左侧树展示节点/网格；支持节点、网格单独显示/隐藏与全部显示/隐藏 |
| 渲染模式 | 实体 / 线框 / 实体+边线（EdgeSettings，阈值 30°） |
| 着色方式 | 光滑 / 平面（`flatShading`） |
| 透明度 | 全局 10%–100%，按材质原始透明度乘算，不破坏模型自带玻璃材质 |
| 单文件上限 | 64MB（base64 走 IPC）；超出提示用系统应用打开或改 zip |

当前支持：**stl / obj / off / ply / 3ds / gltf / glb / 3mf / amf / dae / fbx / wrl**；显式插入的 **zip** 模型包也支持。

### B.1 使用方式

1. 编辑器「插入」→「插入三维模型」，选择文件
2. 文档中出现模型卡片，点「预览」或双击卡片
3. 左侧结构树用 👁 控制节点/网格显示；顶部切换渲染/着色模式、拖动透明度
4. 「实体+边线」首次开启会为每个网格生成边线，大模型可能卡顿数秒

### B.2 维护注意

- 引擎 `Node` 的网格数量方法名是 **`MeshIndexCount()`**；`MeshCount()` 是 `Model` 的方法。此前误用会让 `onModelLoaded` 抛错，界面一直停在加载中。
- 结构树构建失败不应阻塞模型显示：`Viewer3DPreview` 已在建树外包裹 try/catch。
- 引擎按模型材质复用 three.js material，全局透明度/线框会影响共用该材质的所有零件；按节点单独透明需要克隆材质（未实现）。
- 单节点下网格行最多渲染 200 行，超出提示；节点级开关仍可整体控制。
- flat OBJ 可能只有一个根节点 + 大量网格，树深度取决于文件内部 group。

尚未落地（后续阶段）：

- STEP / IGES / BREP / 3DM / IFC：需要 OCCT / rhino3dm / web-ifc，按本文扩展包方案接入；
- 本机回环 HTTP 服务与 iframe 宿主页（当前为内置 React 组件 + File 加载）；
- 多文件伴生（OBJ+MTL、glTF+bin）：当前建议打包 zip；
- 独立全屏窗口、截图、按节点单独透明/材质。

> 说明：内置方案与扩展包方案不冲突。后续接入扩展包时，`Viewer3DPreview` 可切换为 iframe 宿主页，\
> 文档节点与附件路由保持不变。
